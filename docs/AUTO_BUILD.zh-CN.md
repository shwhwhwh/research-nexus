# 自动构建科研系统

RN 0.7 增加自动构建器。在 **DIY 搭建 → 自动构建系统** 输入科研工作流的文字描述，或提供论文链接 / PDF / TXT / Markdown。选择本机已经登录的 Codex 或 Claude Code，点击 **设计并自动构建**。

![自动构建窗口：隔离虚构数据](assets/auto-builder.png)

RN 将按顺序完成：

1. Agent 一次性设计组件清单，并编译每条数据流的执行方案，保存为 Blueprint v2 模板。
2. 检查本机已有组件；复用可用软件，下载并准备缺少的受支持组件。
3. 将模板映射到本机工具和账号，启动并检查需要的 OpenResearch / Zotero 本地服务，逐条验证、运行样例测试，然后部署并启用就绪通道。
4. 点击 **运行该系统** 使用真实接口 / 本次运行输入。可在构建窗口查看结果，或在画布中查看、调整数据流。

首次设计会把本次提交的描述及论文节选交给所选 Agent，使用其已有账号和额度。PDF 最多 12 MB，提取前 40 页、最多 50,000 字。扫描 PDF 需先 OCR。论文中的指令按文档内容处理，不能授权访问其他文件、账号或执行安装命令。

## 模板保存什么

点击 **导出系统模板** 保存 `.rn-system.json` 文件。Blueprint v2 持久化组件配方、服务地址、授权变量名、数据流方向、已编译通道、运行频率和测试样例。它不包含账号密钥、授权同意状态、论文源文件、本机安装路径或构建日志。

其他用户可以从自动构建窗口或系统模板页导入此文件，检查清单后点击 **用此模板自动构建**。RN 直接复用已编译通道并检查本机环境，**无需重新调用设计 Agent**。重复导入复用相同通道和版本，组件下载有缓存，运行回执继续生效。正在运行的系统不会因打开构建窗口而被替换。

实际 Codex 验收：首次设计调用 1 次 Agent；将导出文件重新读入，在禁用 Agent 的情况下完成第二次部署；同一运行输入重复执行，输出无重复条目。此验收使用虚构的本地阅读清单系统，不访问个人科研账号。

## 组件与配置

- 组件配方支持本地目录、网页、HTTP API、alphaXiv、Zotero、OpenResearch、Google Drive、Obsidian、Python、Node.js 和 Git。
- 已安装的软件优先复用，不自动升级。常规软件使用固定包 ID 的 WinGet 配方；下载记录保存版本和文件校验，安装使用该版本。OpenResearch 缺失时，下载官方 Windows CLI 包、验证官方 SHA-256，再准备 RN 管理的 `orx app` 启动器。现有 OpenResearch 安装保持原状。
- 系统权限提示、账号登录、API Key 及 Google Drive 同步目录由用户本人完成。构建窗口显示待办，完成后点 **继续构建**；保留已保存的模板与下载资源。
- 内置账号在 **连接与设置** 中配置。其他 API 的 `NEXUS_` / `RN_` 授权变量可在构建窗口填写，使用 Windows DPAPI 加密保存，按服务地址绑定，不发给设计 Agent、不写入导出模板。
- 新模板不会携带别人固定的 OpenResearch 项目编号或模型分类授权。项目文献模板默认采用本地关键词分类；语义分类需在本机通过项目文献向导授权。

[项目文献 Blueprint](../system-templates/project-literature.rn-system.json) 提供 OpenResearch → alphaXiv 项目收藏、OpenResearch → Zotero 引用笔记与链接 PDF 的编译通道；书签去重归档继续使用原 Template 01。此文件不会自动添加到当前画布，需要用户主动导入。

## 当前执行边界

自动构建器编译并执行 RN 已支持的声明式操作：HTTP 读写、字段选择和映射、筛选、去重、JSON / Markdown 输出以及内置文献连接器。网站没有可用 API、任意模型训练脚本、未知安装配方及尚未实现的适配器，会保存为待完善模板并列明缺失能力，不能伪装成已连接。

部署前的样例测试不访问外部服务、不写入目标账号；真实运行由 **运行该系统** 发起。目录型起点可填写本次运行 JSON，留空时使用模板样例；HTTP 起点会读取真实接口。系统运行支持有向无环图、分支和单路输入；多路合并与反馈环需要另行实现。原有手动画布与单条通道生成仍可使用。

## 开发与验收

模板结构见 [Blueprint v2 schema](../system-templates/blueprint-v2.schema.json)。模板不能提供 shell 命令、本机程序路径或可执行插件；安装命令由 RN 组件配方维护。

- `npm test`：隔离单元与 HTTP 集成测试。
- `npm run test:systems`：隔离桌面导入、构建、运行和布局检查。
- `python scripts/verify-system-builder.py --live-agent --provider codex`：明确调用本机真实 Agent 的可选验收，使用虚构数据与隔离目录，会消耗该 Agent 账号额度。
